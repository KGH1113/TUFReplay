# Camera web crop validation

The companion camera dialog now edits the camera's crop only. Web placement, corner placement presets, game-window width controls, and placement reset have been removed. Position and size are adjusted inside the game.

The dialog opens a browser camera with `getUserMedia({ audio: false, video: ... })` only after **Click to reveal / 클릭해서 보기**. The stream is attached directly to `video.srcObject`; there is no preview IPC, PNG encoding, frame polling, or frame copying. Requested video constraints prefer 720p and 30 fps without browser cropping or scaling, and the editor uses the delivered video's actual width and height to preserve its source aspect ratio. Recording quality in the game remains independent of the browser preview.

Native game device IDs are not browser device IDs. An explicit game camera is matched to a unique normalized browser camera label. When permission is needed to reveal device labels, the temporary default stream is never attached to the video element. It is stopped before switching cameras, and an uncertain or duplicate label match stops it and asks the user to select the browser preview camera. The game's system-default selection can use the browser's default stream directly. No different camera is silently displayed for an explicit game-camera choice.

Every owned track is stopped on close, hide, camera off, connection loss, selected-camera change, tab hiding, page exit, device change, unmount, or preview failure. Late permission grants are stopped without publishing them. A replacement preview does not wait for a previous permission prompt that the user may have ignored. Effects depend on the selected camera's ID and label values, rather than the polled device-array reference, so settings refreshes do not restart a live preview.

Closing and reopening the dialog, switching the selected camera, hiding the preview, or turning the camera off and on requires another reveal. Switching back to a previously revealed camera also remains concealed. The four circular corner controls resize the crop, dragging its center moves it, and the area outside the crop is darkened. Arrow keys provide precise adjustment; Shift uses larger steps. Pointer cancellation, a lost pointer capture, an Escape during a gesture, and a preview resize cancel an unfinished gesture. Crop saves on pointer release; saving and saved feedback appear in the dialog. Mirroring changes only the displayed editing coordinates, and saved crop coordinates always refer to the unmirrored source image.

The source video and pixel plane have no rounded corners, border, or padding. Spacing belongs to an outer wrapper, separate from the absolute crop controls. Every crop handle has an explicit inline zero margin, padding, and border; its center is positioned at the actual corner with `translate(-50%, -50%)`. The former 12-pixel coordinate clamp has been removed. The scrim is clipped in its own inner plane, while corner controls can extend around a source-image edge. Tailwind's `space-y-*` rules generate margin on direct children, so those spacing selectors are kept outside the crop-positioning plane. The crop controls are native buttons; the shared shadcn Button component does not style them.

The crop affects the live and replay display. Full source frames are still stored in recordings. English and Korean descriptions explain this distinction.

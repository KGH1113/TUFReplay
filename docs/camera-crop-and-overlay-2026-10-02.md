# 카메라 크롭과 게임 내 위치·크기 조절

`feat/webcam-recording` 브랜치의 전용 워크트리 `/Users/kgh/dev/src/tuf-replay-webcam`에 구현했다.

- 웹 카메라 설정에서 위치 미리보기, 모서리 위치 프리셋, 크기 슬라이더, 위치 초기화 버튼을 제거했다.
- 게임의 실시간 카메라와 리플레이 영상 위에서는 이동 커서를 표시한다. 모든 변과 모서리에서 방향별 리사이즈 커서를 표시하며, 별도 리사이즈 버튼 없이 크기를 조절할 수 있다.
- 크기를 조절할 때 영상 비율과 반대쪽 앵커를 유지한다. 일부가 화면 밖으로 나가도 조작할 수 있으며, 드래그 종료 시 위치와 크기를 저장한다. 초점 이탈·마우스 버튼 해제·화면 크기 변경에도 조작을 정리하고 기존 커서를 복구한다.
- 웹 카메라 설정에 실시간 원본 미리보기와 크롭 편집기를 추가했다. 네 모서리를 드래그해 영역 크기를 바꾸거나 가운데를 드래그해 영역을 이동한다. 제외한 부분은 어둡게 표시한다. 키보드 방향키와 Shift 조합으로도 조절할 수 있다.
- 미리보기는 **클릭해서 보기 / Click to reveal** 뒤에 표시한다. 크롭 좌표는 미러링 전의 원본을 기준으로 저장하며, 실시간 게임 영상·리플레이·첫 실행 카메라 확인창에 동일하게 적용한다.
- 저장된 MP4는 전체 프레임을 보존하므로 나중에도 크롭을 바꿀 수 있다. 게임 설정의 **Reset camera position**으로 화면 밖의 카메라 위치를 복구할 수 있다.

웹 미리보기는 **클릭해서 보기** 이후 브라우저의 `getUserMedia`로 카메라를 직접 연다. `MediaStream`을 음소거된 `<video>`에 연결하며 원본 비율을 유지한다. 닫기·숨기기·탭 숨김·카메라 끄기·장치 변경 시 미디어 트랙을 종료한다. 게임의 PNG 변환 서비스와 프레임 전송 API는 제거했다. 게임 자체의 카메라 세션과 녹화는 계속 게임이 관리한다.

미리보기의 둥근 모서리를 제거하고, 크롭 손잡이를 여백을 적용하는 레이아웃에서 분리해 각 꼭짓점에 정확히 배치한다.

브라우저 직접 접근으로 전환한 최종 코드의 검증 결과:

- `./scripts/run.sh mod-check`: 성공. macOS 헬퍼 자체 검사, native input 검사, Unity/Mono 호환성, 기존 C# 테스트와 크롭·오버레이 조작 테스트를 통과했다. 모드 빌드는 경고와 오류가 없다.
- `./scripts/run.sh web-check`: 성공. 34개 파일의 웹 테스트 165개, TypeScript, 182개 파일의 Biome 검사, Vite 프로덕션 빌드를 통과했다. 기존 번들 크기 안내만 남아 있다.
- `./scripts/run.sh mod-format check`: C# 파일 64개 통과.
- `git diff --check`: 통과.
- 웹 브라우저 mock의 1280 × 720 `MediaStream` 영상으로 클릭 후 재생, 모서리 드래그, 가운데 이동, 저장 후 설정 재진입, 숨김과 재열기 시 가림을 확인했다. 숨긴 뒤에는 영상 요소가 제거된다. 미디어 트랙 종료와 늦게 도착한 권한 응답 처리도 단위 테스트로 검증했다.
- 원본 미리보기의 border-radius·border·padding과 네 손잡이의 margin은 모두 `0px`이다. 드래그 후에도 네 손잡이 중심과 크롭 꼭짓점의 좌표 오차는 `0px`이다. 390 × 844 화면에서는 모달 너비 358px, 영상 영역 292 × 164.25px로 비율을 유지하며 네 손잡이의 좌표 오차도 `0px`이었다. 임시 뷰포트와 검증 탭은 정리했다. 세부 내용은 [웹 검증 기록](/Users/kgh/dev/src/tuf-replay-webcam/docs/camera-web-crop-validation-2026-10-02.md)에 기록했다.

실제 게임을 실행하거나 모드를 설치하지 않았다. Unity Editor UI 제어가 응답하지 않아 이번 변경의 Editor 실행 검증은 완료하지 못했다. 첫 실행 확인창의 크롭 적용 코드는 모드 빌드에 포함되어 컴파일됐으며, 기존 프리팹의 직렬화 필드는 변경하지 않았다. 실제 카메라 장치와 Windows 런타임 검증은 남아 있다.

적용하려면 위 워크트리에서 `./scripts/run.sh build`를 실행한다. 웹 개발 서버는 같은 워크트리에서 `./scripts/run.sh web-dev` 또는 `bun run web:dev`로 실행할 수 있다.

# 실패 화면 녹화 (키 입력·마이크·카메라)

2026-11-09 Hello (BPM) 2024 0→98% 실패 기록(run `206230cc…`)에서 죽은 뒤 마이크가 없고, 키뷰어에 키가 눌린 채로 남았다.

- 마이크: 녹음 169.76초가 실패 시각(타임라인 165.977초 → 오디오 약 169.77초)에서 정확히 끝났다. 실패하면 `CompleteFailedRun`이 그 자리에서 마이크를 끝냈기 때문이다. 카메라는 2026-10-06(d94ee61)부터 실패 화면을 에디터 복귀까지 찍고 있었다.
- 키: 입력 녹화도 실패 순간에 끝나서 마지막에 6개 키가 눌린 상태로 끝났다. 손을 뗀 기록이 없으니 리플레이(죽는 애니메이션 동안)와 렌더(죽은 뒤부터 영상 끝까지)에서 눌린 채로 보였다.

## 변경

실패한 판도 클리어한 판처럼 실패 화면에서 키 입력·마이크·카메라를 계속 녹화하고, 에디터 복귀·실패 화면에서 바로 재시도·세션 종료 때 저장한다.

- 녹화 데이터: 죽은 시각을 `failedTimeUs`로 따로 저장하고(클리어의 `wonTimeUs`와 같은 역할), `terminalTimeUs`는 녹화가 끝난 시각(에디터 복귀·재시도)이 된다. 죽은 뒤 시간은 클리어 뒤처럼 곡이 아니라 실제 시간을 따른다. 판 길이(`EndedAtUtc`)는 그대로 죽은 순간에 끝난다.
- 녹화 흐름: 실패해도 판을 바로 저장하지 않는다. `FinishFailedRun`이 실패 화면이 끝날 때 입력을 멈추고 판을 저장한 뒤 마이크·카메라를 끝낸다. 재시도는 `Countdown`/`Checkpoint` 상태에서 입력 타임라인을 끊기 전에 이전 판을 저장해서, 재시도 키까지 이전 판에 들어간다. Fail 안에서 마지막 판정을 기다리던 `_failedRunWaitingForHit`은 저장이 늦춰져 필요 없어져서 지웠다. 보정(calibration) run은 그대로 실패 즉시 끝낸다.
- 게임 안 리플레이: 실패한 판의 리플레이는 죽은 시각에 끝난다(`ResolveReplayEndTimeUs`). 실패 화면에서는 아무 키나 누르면 레벨이 재시작되므로 게임에는 죽기 전 키만 보내고, 죽으면 게임에 보낸 키를 뗀다. ReplayApi 키(Element 등)는 죽는 애니메이션 동안 실패 화면 키를 계속 받는다(`TickFailScreenKeys`, 실제 시간 시계 `EnterFailed`). 리플레이가 Fail2에서 끝나므로 그 뒤는 보이지 않는다.
- 렌더: `failedTimeUs`에 죽고, 그 뒤 실패 화면 키·마이크·카메라를 녹화 끝까지 보여 준 뒤 결과 화면 유지 시간을 더한다. 영상이 클리어처럼 에디터 복귀·재시도 시점까지 길어진다. OrbitRender에는 `wonTimeUs` 자리에 실패 시각을 넘겨서, 카메라가 죽은 뒤 실제 시간을 따르게 했다. 렌더 중에는 `Fail2_Update`가 막혀 있어서 실패 화면에서 레벨이 재시작되지 않는다.
- 이전 기록(`failedTimeUs` 없음): 그대로 `terminalTimeUs`에 죽고, 그때 눌려 있던 키를 뗀다. 이전 기록의 실패 화면 입력·마이크는 복구되지 않는다.

## 검증

`./scripts/run.sh mod-check` 통과.

- `WebcamSuite.FailedRunCaptureSurvivesUntilEditorOrRetry`: 실패하지 않은 판에서는 아무것도 끝내지 않고, 에디터 복귀·재시도 모두 카메라와 마이크를 한 번씩만 끝내며, 재시도 run에 실패 상태가 남지 않는다.
- `RenderHostSuite.FailedRunsRecordTheFailScreen`: 실패 시각에 죽고, 실패 화면 키를 읽고, OrbitRender가 죽은 뒤 실제 시간을 따르며, 잘못된 `failedTimeUs`를 거부한다.
- `ReplayNativeInputSuite`: 실패한 판의 게임 안 리플레이는 죽은 시각에, 이전 기록과 클리어는 녹화 끝에 끝난다.

게임 안에서는 확인하지 않았다.

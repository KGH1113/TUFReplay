# Auto submission 확정 사항 — 2026-09-08

이 문서는 사용자와 확인한 제품 계약이다. 기존 구현 상태 문서와 단계별 초안보다 우선한다. 구현 완료 여부는 별도로 검증한다.

추가 확인: 공식 OAuth client ID와 자동 제출 서버 주소는 아직 미정이므로 모드 설정으로 주입하며, 누락 시 로그인을 비활성화한다. `keyCount`는 플레이 중 실제로 눌린 서로 다른 키 수다. 반복 입력, 키 해제, 클리어 이후 입력은 개수를 늘리지 않는다.

## 책임과 인증

- 기존 영상 제출을 유지하고 공개 P1–P20/G1–G20 자동 제출을 추가한다. 최종 관리자 심사는 없다.
- 웹은 UI이며 로그인·설정·목록·제출·삭제를 IPC로 모드에 요청한다. 웹에서 API를 직접 호출하거나 OAuth 토큰을 보관하지 않는다.
- 모드가 OAuth 클라이언트와 자동 제출 API 클라이언트다. 웹에서 인증을 시작하고 모드의 OS 보안 저장소에 갱신 자격 증명을 보관해 다음 실행에도 유지한다.
- TUF 기존 OAuth Authorization Code + PKCE를 사용하고, 자동 제출 동의는 지정한 공식 OAuth 앱에만 허용한다.
- 로그인은 필수다. 현재 기기의 로그아웃은 다른 기기에 영향을 주지 않는다. OAuth 앱 권한 철회는 모든 관련 연결에 적용한다.
- 로그아웃·권한 철회 시 진행 중 수집은 중단한다. 정상 토큰 갱신은 로그아웃이 아니다.
- 같은 계정의 동시 플레이 수집은 하나다.
- internal API는 방향별 고정 서버 토큰으로 보호한다. `TUF_TO_AUTO_SUBMISSION_TOKEN`과 `AUTO_SUBMISSION_TO_TUF_TOKEN`은 서로 다른 값으로 환경변수에서만 읽는다. 일반 사용자 OAuth/사이트 토큰으로 internal 등록 권한을 얻을 수 없어야 한다.
- 자동 제출 서버가 입력과 판정을 검증한다. 모드는 게임에서 배속·키 수·플레이 속성·게임 버전을 읽는다. TUF는 검증 결과로 기존 accuracy와 점수를 계산한다.

## 플레이·제출

- TUFHelperLite 설치 정보를 이용해 차트를 식별한다. 수동 설치 차트 연결 UI는 이번 범위에서 제외한다.
- Strict만 인정한다. 배속은 기존 TUF의 1–100 범위다.
- NoFail 자체는 제외 사유가 아니다. 실제 실패 없는 클리어인지 검증해야 한다.
- 플레이 도중 일시정지하면 자동 제출에서 제외한다.
- 로그인 상태에서는 수집이 기본 활성화된다. 사용자가 비활성화할 수 있으며 설정을 유지한다.
- 비활성화는 현재·향후 플레이 수집만 중단한다. 기존 기록 조회·제출과 이미 접수된 검증은 유지한다.
- 업로드 끊김은 30초 이내, 버퍼 손실 없이 복구된 경우만 인정한다. 게임과 로컬 녹화는 서버 장애와 무관하게 계속한다.
- 모드의 복구 시계는 네트워크 오류 감지 시 시작한다. 30초 미만에 handshake가 완료돼야 하며 복구 후 타이머·대기 횟수를 초기화한다. 재시도는 0.2초씩 증가해 최대 2초 대기하고, 횟수만으로 조기 종료하지 않는다. 연결·hello·응답을 포함한 재연결 시도는 남은 시간으로 제한한다. 물리적 단절의 감지는 기존 I/O timeout(작업당 8초)에 따라 늦어질 수 있다.
- 일일 고정 업로드 한도는 없다. 개별 증거 용량과 기술적 자원 한도는 부하·발생량 측정 후 결정한다. 초안의 128 MiB/6시간/분당 5회 제한은 확정 정책이 아니다.
- 클리어만으로 의미 검증하지 않는다. 제출 버튼 한 번으로 검증부터 등록까지 수행하며 추가 폼 입력은 없다.
- 별개 플레이는 판정이 같아도 별도 pass로 등록한다. 같은 run의 재요청만 멱등 처리한다.
- 일시적인 서버 오류는 제한된 자동 재시도 후 사용자가 다시 시도할 수 있는 상태로 전환한다.
- 서버에 접수된 제출은 게임 종료 후에도 처리한다. 결과는 다음 접속 때 조회한다.
- 등록 알림은 제출 화면의 성공 결과와 pass 링크로 제공한다. 개인 알림함·Discord 공지는 이번에 추가하지 않는다.

## 공식 차트·보관

- 공식 차트는 제출 후 검증 단계에서만 임시 다운로드한다. 플레이 준비 시 원본을 다운로드하거나 영구 카탈로그에 저장하지 않는다.
- 검증 당시 공식 차트를 기준으로 검사한다. 예전 공식 차트를 찾아서 호환성을 보장하지 않는다. VFX 차이와 file ID 변경만으로 바로 거절하지 않는다.
- 제출 완료 리플레이에는 검증 당시 차트의 versioned 의미 gameplay hash를 기록한다. 이후 현재 공식 file ID나 전체 파일 SHA가 달라도 의미 해시가 같으면 현재 archive로 재생하며, gameplay hash가 다르면 재생을 거절한다.
- 검증용 차트 원본·압축 파일은 성공 여부와 관계없이 정리한다. 성공한 .adofai도 영구 보관하지 않는다.
- 정상 미제출 증거는 기한 없이 보관한다. PostgreSQL에는 상태·manifest, Storage에는 증거 파일을 보존하며 사용자가 나중에 제출할 수 있다. Redis 완료 응답의 24시간 보존과는 별개다.
- 제출 완료 증거는 pass가 유지되는 동안 보관한다. pass 숨김·삭제 시 비공개로 보관해 복원·운영 검토에 사용한다.
- 향후 공개 원칙은 제출 완료 후 재생용 증거 공개다. 인증 정보와 내부 진단은 공개 대상이 아니다.
- 이번에는 TUF에 자동 제출 출처·run 식별자를 기록하고 조회 응답에 제공한다. 공개 증거 API·iframe 재생 UI는 후속 작업이다.
- 원본을 보관하지 않으므로 향후 공식 차트 변경·삭제 시 당시 차트 그대로의 재생은 보장하지 않는다.

## 작업 경계

- 시뮬레이터는 구현 범위에서 제외한다. 미구현 검증기는 명시적으로 unavailable을 반환해야 하며 실제 pass를 허위 승인하지 않는다.
- 실제 게임 실행 검증은 사용자가 한다. 에이전트는 빌드·계약·서버·웹 테스트를 수행한다.
- SOLID와 파일별 단일 레이어 책임을 지킨다. TUF backend는 인접 코드의 공백·줄바꿈·파일 분리·오류 처리·서비스 관례에 맞춘다.
- TUF backend 작업 전 미추적 항목 네 개만 폐기한다: `.DS_Store`, `.playwright-cli/`, `src/database/scripts/export_curated_charts.sql`, `src/database/scripts/mysql_batch_to_csv.py`.
- 에이전트의 backend 초안은 전부 폐기하지 않고 위 계약에 맞게 수정한다. 관련 없는 변경과 의존성 파일을 일괄 초기화하지 않는다.
